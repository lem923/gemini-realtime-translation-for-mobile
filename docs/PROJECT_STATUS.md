# 项目状态

> 最后更新：2026-08-13

`gemini-realtime-translation-for-mobile` 是一个 Android 优先、面向出国旅行双人对话的实时翻译器。应用使用 Flutter 复用产品、协议和状态管理代码，通过 Google Gemini Live API 的 `gemini-3.5-live-translate-preview` 模型同时输出原文、译文和翻译语音。

当前处于预览与工程验证阶段，不应视为已经完成生产验收的应用。Android 是第一个交付平台；iOS 将在 Android 真机验证和体验目标稳定后补齐原生适配。

## 已完成

### 核心翻译体验

- 用户手动选择讲话人 A 或 B，明确控制翻译方向；自动识别讲话人不在当前范围内。
- 支持标准对话布局和面对面布局，展示实时原文与译文，并播放 24 kHz PCM 翻译语音。
- 支持可搜索的语言选择、交换语言、静音、停止、内存内历史记录和有上限的译音回放。
- 使用两条方向会话减少切换等待；切换讲话人时隔离旧方向的迟到事件并发送音频流结束边界。
- 覆盖连接中、重连、离线、配额限制、麦克风拒绝、鉴权失败和服务异常等可恢复状态。

### Gemini 与共享核心

- 客户端直接连接 `gemini-3.5-live-translate-preview`，输入为 16 kHz、单声道、16 位 PCM，输出为 24 kHz、单声道、16 位 PCM。
- 解析源语言转写、目标语言转写、音频、会话恢复、服务器迁移提示、上下文压缩和用量元数据。
- WebSocket、录音、播放、权限和安全存储均通过明确接口与共享状态机衔接；Dart 业务代码不依赖 Android 实现类。
- 队列、回放缓存、历史记录、重连次数和上下文均有边界，避免长时间运行时无限增长。

### Android 实现

- 支持 Android 8.0 / API 26 及以上版本。
- 录音采用面向通话的 16 kHz 音频配置；原生 `AudioTrack` 播放采用 24 kHz 流式输出和有上限的队列。
- 原生层统一管理通信模式、音频焦点、输出路由、系统中断和资源释放，避免录音与播放组件争夺同一音频状态。
- 对扬声器/听筒与有线、USB、蓝牙、助听器等隔离路由采用不同的半双工回声保护时长。
- 应用进入后台或遭遇音频焦点中断时停止会话并释放录音、播放、路由和通信模式。
- 已配置专用发布签名流程；签名材料不进入仓库。

### UI、可访问性与诊断

- Material 3 明暗主题、标准/面对面布局和移动端大触控区域已经实现。
- Widget 测试覆盖动态状态播报、错误 live region、讲话人语义、Android 48 dp 触控目标、可访问名称、明暗主题文本对比度、RTL 和 200% 字体缩放。
- 运行诊断只汇总时延、队列、重连、失败、方向切换和 Token 计数，不包含 API Key、PCM、原文或译文。

## BYOK 与隐私边界

- 应用没有账号系统、项目后端、媒体中继、云端对话存储或默认分析 SDK。
- 用户必须提供自己可用的 Gemini API Key；没有 Key 或验证失败时不能开始翻译。API 用量、配额与可能产生的费用由用户对应的 Google 项目承担。
- Key 默认只保存在应用进程内存中。用户明确选择“记住”后，才交给操作系统支持的安全存储；可随时在应用中移除。
- 麦克风音频、源语言转写与翻译请求会从设备直接发送给 Google Gemini 处理，受 Google Gemini API 的条款与数据政策约束。
- 当前对话文本和译音回放只保存在内存中，停止应用进程后消失；语言对属于非敏感偏好，会保存在本地以便下次恢复。
- 应用默认不记录 API Key、原始音频或对话文本；请勿在 issue、日志或截图中公开自己的 Key 或敏感对话。

## 当前限制与未完成门槛

- `gemini-3.5-live-translate-preview` 是预览模型；可用性、协议、配额、并发限制、语言质量和价格均可能变化。
- 当前交互是用户主动切换讲话人、一次只采集一个方向的半双工对话，不是多人会议、免触控自动轮转或离线翻译。
- 两条预热方向会话可能受用户项目的并发配额影响；受限时需要退化或重试策略，不能保证所有 Key 都能同时保持两条连接。
- 尚未在代表性 Android 真机矩阵上完成扬声器声学回声、嘈杂街道、弱网络、有线耳机、USB 与多种蓝牙设备的量化验收。
- 当前时延与稳定性证据主要来自自动化、主机工具和模拟器；生产目标仍需在真机记录端到端首字、首音频、丢帧、重连和长时温升/耗电。
- 不支持后台持续翻译；进入后台会主动停止媒体和 Gemini 会话以保护隐私并释放系统音频资源。
- iOS 只有 Flutter 宿主工程、资源和可复用共享边界。`AVAudioSession`/`AVAudioEngine` 音频、路由、中断、权限、Keychain 行为和物理 iPhone 验证尚未完成，因此当前不能宣称 iOS 可用。

## 下一步

当前工作的唯一发布主线是完成 Android 真机矩阵和量化验收，处理发现的问题，再发布 Android 候选版本。随后才进入 iOS 原生适配与同等场景验证。具体执行顺序见 [Roadmap](roadmap.md)，本地运行与构建方式见 [Quickstart](../QUICKSTART.md)。
